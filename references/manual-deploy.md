# 手动拖拽部署（agent 代打参考）

> 2026-11-03 在 TR-28（主线 17 章教学关，0 理智）实测通过的全链路。
> 用途：作业缺失/作业失效时的**手动兜底**——活动刚更新、作业站还没轴、
> 或者像模组任务这种"要求特定干员上场"的自定义条件关。

## 已验证的完整链路（adb 1920×1080）

```
1. 点选干员卡      input tap <卡片x> <卡片y>
   → 卡片抬起，左下弹出干员详情，地图上绿色可部署格高亮
2. swipe 拖到目标格  input swipe <卡x> <卡y> <格x> <格y> 500
   → 白色菱形范围 + 橙色朝向杆 = 部署预览态
3. 确认朝向         input swipe <格x> <格y> <格x> <格y-150> 300   （朝上为例）
   → 干员落地，费用扣除，剩余可放置 -1
4. 截图验收         干员立绘出现在格上即成功
```

实测数据（TR-28，米格鲁 18 费）：
- 部署前：剩余可放置 4、费用 42；部署后：3、24。数字变化即验收依据。
- swipe 时长 400~700ms 都能被识别；太短（<200ms）会被当成点击。
- **先点选再拖**比直接从栏里拖更稳（直接拖偶尔被当成滑动地图）。

## 节奏问题与对策（TL-1 三连败的教训）

agent 一轮操作 = 截图(2s) + 决策(1s) + 发送(1s) ≈ **5 秒**。
TL-1 这种 21 敌 3 血的开局扛不起 5 秒延迟。对策：

1. **选宽容的关练手/执行**：0 费教学关（TR-xx）、敌人慢的关、
   或者开场给足费用缓冲的关。TR-28 是完美实验场（0 理智无限重试）。
2. **开战后立即暂停**：暂停态可以部署，随时截图。暂停键 (1822,88)。
   注意截图偶发全黑（screencap 竞态），重试一次即可。
3. **预计算好落点再开战**：先看敌方情报/地图确定部署格，
   开战后按既定清单执行，减少中间决策。

## 教学关的对话干扰

TR 类教学关开场有强制对话，点 (700,60) 可推进，但**游戏会在
"等你执行教学动作"处停下来**（画面出现橙色箭头指引 + 高亮格），
此时对话点不掉、必须完成指定动作才能继续——正好是被验证的拖拽时机。

## 退出不亏

- **TR 教学关**：0 理智，放弃/打输都无损。
- **推演模式**（主线险地作战）：放弃返还全部理智。
- 普通关放弃：按完成度比例返还，仍建议在编队页就确认好再进。

## 模组任务自动化：已验证全流程（凛御银灰 CSR-X 邀约，2026-11-03 实战）

**结果：两个任务 + 解锁全部自动化完成，零手搓。** 路线比当初评估的更顺：
prts 上有现成的「模组任务专用作业」（作者已按任务条件配好限编队），
不用自己换人，只要往 JSON 里补技能动作。

### 第一步：找关卡内部 ID（显示代码 ≠ 搜索关键词）

`copilot_search("BI-7")` 返回 0——prts 的 levelKeyword 只认内部 ID。
stage_map.json 里也没有 BI 映射。反查方法（权威且离线）：

```bash
python - <<'EOF'
# MAA 资源里每关的 tile-pos JSON 都带 code 字段
import json, io, glob
for f in glob.glob(r'<MAA_DIR>\resource\Arknights-Tile-Pos\*.json'):
    d = json.load(io.open(f, encoding='utf-8'))
    if d.get('code','').startswith('BI-'):
        print(d['code'], d['levelId'])
# -> BI-7 = act14side_07（风雪过境）
EOF
```

### 第二步：搜「模组任务专用」作业并核对条件

`copilot_search("act14side_07")` → 33 个作业，其中标题带「模组任务」的
（如 108783「凛御银灰 X模组BI-7」）就是按任务条件写的：
凛御银灰+圣聆初雪双人队（天然满足"其他成员≤7"）、双任务一局完成。
用 `CA.feasible()` 核对练度（作业要求 E2 60，账号 E2 70 ✓）。

### 第三步：改造 JSON——补技能动作（关键）

模组作业的通病：**作者只写 Deploy，技能要人手放**（108783 作者原话
"不知道为什么银灰不放技能，手动放一下把"）。任务 1 要数技能次数，
不补动作就永远 1/8。改造三件套：

```python
cop['opers']  # 凛御银灰那条加：
  "skill": 2          # 任务指定技能「御敌的锋锐」是 2 技能，编队必须选对
  "skill_usage": 1    # MAA「好了就开」——主力保险
cop['actions']  # Deploy 后追加 8 个显式动作（2 充能 17SP 技能，19s 间隔够回蓝）：
  {"name": "凛御银灰", "type": "Skill", "pre_delay": 19000}
# 结尾保留 {"type": "SkillDaemon"}
```

实测 19s×8 的显式动作 + skill_usage=1 双保险：断线前 MAA 日志每
~100s 一条「使用技能 凛御银灰」，一局放满 7 次，两局累计 8/8。

### 三个实战坑（都踩过）

1. **`run_stage.py --job <id>` 会重新从 prts 拉原始作业**，本地改造版被
   绕过——第一局就是这样只放了 1 次技能（初始 SP 满了一层）。
   用本地文件必须 monkeypatch：

   ```python
   meta = {'content': json.dumps(cop_local, ensure_ascii=False)}
   CA.fetch = lambda cid: meta   # 再调 run_stage.run(...)
   ```

2. **MAA 任务链独立于驱动脚本**：python 超时返回 FAILED 后 MAA 照样在
   打在放技能（日志继续出「使用技能」）。别看到脚本超时就当失败——
   以 gui.log + 游戏内任务面板为准。这局就是这样断线前放满了技能。

3. **MAA 高频截图期间 adb 会 offline**（exec-out screencap 30s 超时）：
   `adb disconnect && connect` 不行就 `taskkill adb.exe` + `start-server`
   重来；都不行重启模拟器+MAA（实测电脑重启后 30s 内恢复）。

### 导航捷径

去老活动关卡别走 乐章收录→滚动→封面 的长路（中途弹签到/公告窗还会
点歪进充值页）。打完一局后，**主界面右下「前往上一次作战」横幅直接
显示刚才的关卡**（如"活动 BI-7 破冰"），一点直达关卡页。

### 收尾

任务全勾后：干员页 → 干员 → 管理+ → 解锁 → 弹「是否解锁邀约?」点 ✓
（材料 70/60、123/4、9/2、80000 全黄才可点）→ 模组展示页（AUTHORIZED）
→ ✓ 关闭。解锁消耗材料，属预期支出。

## 局限（诚实边界）

- 只适合**非时序敏感**的场景。卡秒轴请用 MAA 作业。
- 朝向确认目前用"从格心向上滑"的固定动作，任意朝向需按箭头方向算偏移。
- 底部干员栏超过一屏时要先滚动，滚动后卡片坐标会变，需重新截图定位。
